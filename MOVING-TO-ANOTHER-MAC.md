# Moving this project to another Mac

The project itself is small — about 1.6 MB of source. Everything else
(`build/`, `dist/`) is regenerated by `./build.sh`, and the photographs and
settings live outside the project entirely.

## 1. The code — a private GitHub repository

This folder is now a git repository with one commit. On github.com make a
**private** repository called `photobooth-mac` (no README), then here:

```bash
git -C ~/Movies/Work/CLAUDE/Photobooth remote add origin https://github.com/<you>/photobooth-mac.git
git -C ~/Movies/Work/CLAUDE/Photobooth push -u origin main
```

On the Mac Mini:

```bash
mkdir -p ~/Movies/Work/CLAUDE && cd ~/Movies/Work/CLAUDE
git clone https://github.com/<you>/photobooth-mac.git Photobooth
```

**Keep the same path** — `~/Movies/Work/CLAUDE/Photobooth` — if you want Claude
Code to pick up the notes it has been keeping about this project. Those notes are
filed under a folder named after the project path, so a different path is a
different (empty) history.

From then on, `git pull` before you start and `git push` when you stop, on
whichever Mac you are using.

## 2. What the Mini needs before it can build

```bash
xcode-select --install                      # swiftc, clang, git
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install libgphoto2 libexif
```

`build.sh` asks Homebrew where those two libraries are, so they must be
installed to build. They are **not** needed to *run* the app — the finished
`Photobooth.app` carries its own copies, which is why the DMG works on a clean
Mac.

Then:

```bash
cd ~/Movies/Work/CLAUDE/Photobooth && ./build.sh && ./make_dmg.sh
```

## 3. Your settings, and the photographs

None of this is in the repository, deliberately — a client's photographs do not
belong in source control.

| What | Where | Move it? |
|---|---|---|
| Settings, upload queue | `~/Library/Application Support/Photobooth/` | Yes, to carry your setup across |
| Photographs | `~/Pictures/Photobooth/` | Only if you want the back catalogue on the Mini |
| Album pages | `~/Documents/photobooth-albums/` | Yes if you have albums out with clients |
| Local site folder | `~/Documents/photobooth-site/` | No — unused since GitHub Pages was dropped |

Copy them with AirDrop, an external disk, or over the network:

```bash
rsync -av ~/Library/Application\ Support/Photobooth/ macmini.local:~/Library/Application\ Support/Photobooth/
```

After copying the settings, check **Admin › Printer** on the Mini: the SELPHY
has to be added in System Settings there first, and the printer name is part of
the settings you just copied.

## 4. Permissions the Mini will ask for again

These are per-machine and per-build, so expect to redo them:

* **Input Monitoring** for the USB booth button — Admin › Booth Button › Grant
  Access. The app is ad-hoc signed, so macOS asks again after each new build.
* **First launch**: right-click Photobooth › Open, then Open in the dialog.
* **Camera**: quit Image Capture and Photos before connecting the 6D.

## 5. What is *not* portable

* The **Cloudinary** cloud name and unsigned preset live in your settings — they
  come across with the settings file.
* The **album passwords** are stored per event in the sessions folder. Copy the
  photographs folder and they come with it; leave it behind and the albums you
  have already sent still work, but the app will not know their passwords.
